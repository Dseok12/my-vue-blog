# Vue.js 풀스택 학습 로드맵 — 컴퓨터를 켜는 법부터 어떤 서비스든 만드는 사람까지

이 폴더는 **프로그래밍을 한 줄도 써 본 적 없는 사람**이 시작해서,
**Vue + Node.js + MySQL 로 원하는 웹 서비스를 혼자 설계하고, 만들고, 배포할 수 있는 사람**이 되는 것을 목표로 한다.

교재의 모든 예제는 이 저장소의 실제 프로젝트 "나만의 다양한 diary" 와 연결된다.
배운 것이 실제 코드에서 어떻게 쓰이는지 항상 확인할 수 있다.

아래 질문에 **"예"** 라고 답할 수 없는 첫 번째 단계부터 시작한다.

| 질문 | 아니오라면 |
| --- | --- |
| 터미널에서 폴더를 만들고 이동할 수 있고, `node -v` 의 결과를 본 적이 있다 | 00 |

## 3. 학습법 — 이 커리큘럼이 효과가 있는 이유

### 3-1. 다섯 가지 원칙

**① 눈으로 읽지 말고 손으로 친다.**
복사·붙여넣기는 금지다. 오타를 내고, 오류를 보고, 고치는 과정이 곧 학습이다.
읽기만 하면 "아는 느낌"만 남고, 막상 빈 화면 앞에서는 한 줄도 못 쓴다.

**② 같은 것을 세 번, 매번 다르게 한다. (3회독)**

| 회독 | 방법 | 얻는 것 |
| --- | --- | --- |
| 1회독 — 따라 만들기 | 문서를 보며 그대로 친다. 이해가 안 가도 일단 동작시킨다 | 지도 |
| 2회독 — 백지 재현 | 문서를 **덮고** 과제를 만든다. 막히는 곳만 다시 연다 | 이해 |
| 3회독 — 변형 | 요구사항을 바꿔 다시 만든다 | 응용력 |

2회독에서 막히는 곳이 **아직 모르는 곳**이다. 거기만 1회독을 다시 한다.

**③ 매일 조금씩, 그리고 다음 날 복습한다. (간격 반복)**
주말에 8시간보다 매일 1시간이 훨씬 오래 남는다. 매일 시작할 때 **어제 배운 것을 5분간 백지에 적어 본다.**
적지 못한 것이 오늘 다시 볼 것이다.

**④ 남에게 설명해 본다. (파인만 기법)**
"ref 는 값이 바뀌면 화면이 바뀌는 상자다" 처럼 **초등학생에게 설명하듯** 학습 일지에 적는다.
설명이 막히는 곳은 이해하지 못한 곳이다.

**⑤ 작은 것이라도 끝까지 완성한다.**
90% 완성한 프로젝트 10개보다 100% 완성한 프로젝트 1개가 낫다.
마지막 10%(오류 처리, 빈 화면, 모바일, 배포)에서 실력이 가장 많이 는다.

### 3-2. 하루 루틴 (1시간 30분 기준)

```
 5분   어제 배운 것을 백지에 적기 (복습)
50분   오늘 분량 1회독 또는 과제 (타이머를 켠다)
10분   쉬기 — 자리에서 일어난다
20분   백지 재현 과제 또는 확장 과제
 5분   학습 일지 쓰기
```

### 3-3. 학습 일지 양식

저장소에 `study/my-log.md` 같은 파일을 만들고 매일 적는다. (Git 으로 커밋하면 잔디가 쌓인다)

```markdown
## 2026-11-01 (03 JavaScript — 배열 메서드)

- 오늘 배운 것: filter 는 조건에 맞는 것만 골라 "새 배열"을 만든다. 원본은 그대로다.
- 내 말로 설명: map 은 "모든 요소를 변신시킨 새 배열", filter 는 "통과한 요소만 모은 새 배열"
- 막힌 곳: reduce 의 두 번째 인자(초기값)를 빼먹으면 왜 결과가 이상한지
- 해결: 초기값이 없으면 첫 요소가 초기값이 된다. 객체 배열에서는 반드시 넣는다.
- 내일 할 것: reduce 연습 문제 3개, 백지 재현
```

### 3-4. 막혔을 때 — 20분 규칙

```
1) 오류 메시지를 끝까지 읽는다. (영어라도 번역기에 넣는다. 90% 는 여기서 답이 나온다)
2) 오류가 난 파일과 줄 번호를 연다. console.log 로 값을 찍어 본다.
3) 오류 메시지를 그대로 검색한다. (따옴표로 감싸면 정확히 일치하는 결과)
4) 공식 문서에서 해당 기능을 찾는다.
5) 20분이 지나도 안 되면 질문한다. ← 혼자 2시간 붙잡지 않는다
```

**좋은 질문 양식** — 이렇게 적다 보면 절반은 스스로 답을 찾는다.

```
[하려는 것]   글 목록에서 좋아요를 누르면 숫자가 바뀌게 하려고 합니다.
[한 것]       LikeButton.vue 에서 store.toggleLike 를 호출합니다. (코드 첨부)
[기대한 결과] 숫자가 3 → 4 로 바뀜
[실제 결과]   숫자가 그대로이고, 새로고침하면 4 가 됨
[오류 메시지] 없음
[시도한 것]   console.log 로 응답을 찍어 보니 likeCount: 4 가 옵니다.
```

### 3-5. AI 도구 쓰는 법

AI 는 **24시간 옆에 있는 선배**로 쓰면 최고의 도구고, **정답 자판기**로 쓰면 실력이 멈춘다.

| 좋은 사용 | 나쁜 사용 |
| --- | --- |
| "이 오류 메시지가 무슨 뜻인지 설명해 줘" | "이 오류 고쳐 줘" 하고 결과만 붙여넣기 |
| "내 코드에서 ref 를 reactive 로 바꾸면 무엇이 달라져?" | "할 일 앱 만들어 줘" |
| "내가 쓴 설명이 맞는지 확인해 줘: computed 는 …" | 이해하지 못한 코드를 커밋 |
| 내가 먼저 짠 다음 "더 나은 방법이 있을까?" | 문제를 읽자마자 질문 |

**규칙: AI 가 준 코드는 한 줄씩 설명할 수 있을 때만 쓴다.** 설명할 수 없으면 다시 물어본다.

## 6. 이 프로젝트 실행하기

```bash
# 프론트엔드만 (백엔드 없이 브라우저 저장소로 동작)
cd frontend
npm install
# frontend/.env 에서 VITE_USE_MOCK=true
npm run dev          # http://localhost:3000  (체험 계정 demo@diary.test / demo1234)

# 백엔드까지 (MySQL 필요)
cd backend
npm install
cp .env.example .env # MySQL 정보 입력
npm run db:migrate && npm run db:seed
npm run dev          # http://localhost:4000/api/health
```

자세한 내용은 저장소 맨 위의 [README.md](../README.md).
